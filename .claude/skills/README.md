# Skills

Skills are reusable workflows that Claude Code auto-discovers here. Each skill is a folder containing a `SKILL.md`:

```
.claude/skills/<skill-name>/SKILL.md
```

Codex discovers skills in `.agents/skills/`, where each entry is a symlink back to the folder here, so both agents run the same copy. When you build a new skill, create it here and add the matching symlink (`ln -s ../../.claude/skills/<skill-name> .agents/skills/<skill-name>`). The one exception is `ingest`, described below.

Build skills organically: when you notice you are repeating the same request, turn it into a skill.

Every skill folder also carries a `MEMORY.md`: a free-form file the skill reads at the start of each run and appends to **only when hcho explicitly says to remember something**. Keep it under 100 lines. When you build a new skill, scaffold a `MEMORY.md` and add a `## Memory` section to its SKILL.md following the same read-on-start, feedback-gated-write pattern.

## Active skills

- **application-packet:** builds one role's Application packet from the Master profile (`projects/Job_Search/profile/`): a one-page resume (.pdf and .docx) whose every line cites evidence-backed Claims, answers for the form's actual text fields, and a gaps-to-own note. `projects/Job_Search/applications/build_packet.py` refuses unsupported numbers, retired phrases, stale numbers, and anything over one page. Asset: `application-packet/assets/packet-template.yaml`. This folder is the canonical copy; `.agents/skills/application-packet` is a symlink to it so Codex and Claude Code cannot drift.
- **job-hunter:** searches direct employer pages, full-time aggregators such as Indeed, and freelance marketplaces led by Upwork, then ranks opportunities by resume fit and engagement quality. Assets: `job-hunter/assets/companies.yaml` (Tier A/B/C company list) and `job-hunter/assets/search-sources.yaml` (the default source mix). References: scoring rubric, ATS patterns, company-list buckets.
- **daily-log:** creates or opens today's daily log for a tracked project path such as `projects/RepToday` or `projects/Immerse`, carrying forward the previous log's "Next" items. Asset: `daily-log/assets/daily-log-template.md`.
- **daily-loop:** runs hcho's daily operating loop: a morning brief, one focused project block, and an end-of-day closeout.
- **gr0wthlab-reader:** reads gr0wthlab's Review Queue, items, run reports, Weekly Read memos, and hcho's records (including the Weekly Read numbers he types on its sitting page) from its production clone (`~/gr0wthlab/ledger/`) to show status, applies a Go-To-Market Package change only when gr0wthlab's queue closed the item as approved and his decision record says approve, and gives hcho an approved Dispatch request to pass to firstmate. It never writes to gr0wthlab and never records a decision or a result; hcho decides and gives his numbers on gr0wthlab's sitting page. Contract: gr0wthlab's `docs/mandu-exchange.md`, version 8. This folder is the canonical copy; `.agents/skills/gr0wthlab-reader` is a symlink to it.
- **influencer-marketing:** vets and re-picks the creators gr0wthlab writes to, using the vetting checklist and a one-off by-hand creator search (`influencer-marketing/references/creator-scouting.md`) for creators of about 5,000 to 10,000 followers. Copied from [coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills) at commit `e85f3cbc`, MIT; its paid, gifting, sponsorship, and whitelisting parts are cut (listed in `influencer-marketing/LICENSE.md`). It drafts only, reads strategy from the product's Go-To-Market Package (`projects/RepToday/gtm/` for RepToday), never sends, pays, or gifts, and never requests a path a host's `robots.txt` disallows. `.agents/skills/influencer-marketing` is a symlink to it.
- **customer-research:** turns Reddit threads and App Store reviews hcho read and copied by hand into sourced, confidence-labeled quotes for the Go-To-Market Package's research files ("Analyze Existing Assets" mode). Copied from the same library and commit, MIT; its incentive and proxy-persona parts are cut (listed in `customer-research/LICENSE.md`). It never fetches pages against `robots.txt`, invents or paraphrases a quote, or changes Angles during a window. `.agents/skills/customer-research` is a symlink to it.
- **gr0wthpilot:** takes one of hcho's existing Products and writes its Candidate Package in `projects/<Product>/` (`gtm/`, or a dated `gtm-candidate-<date>/` beside an earlier Candidate Package or a live one; a Product is handed off when gr0wthlab's product list names its package): research by parallel agents, a blind name and positioning tournament with judge panels, skeptics on every load-bearing claim, brand guidelines with a fresh-agent test, a landing page, the 14-day Test Kit gr0wthlab runs, a Launch Set for Instagram, X, and TikTok, a walkthrough video of real app screens, a red team, and a recap ending in the Handoff line. hcho starts it with `bin/gr0wthpilot <Product>` from Mandu's root, which opens a Claude Code session under a guarded permission profile (a guard hook, permission rules, and the macOS sandbox; `gr0wthpilot/references/guardrails.md`) that refuses anything that publishes, spends, or writes outside the Candidate Package, keeps the guard's own records where the run cannot write, and resumes from the last passed gate when started again. Its check scripts and their tests are in `gr0wthpilot/scripts/` and `gr0wthpilot/tests/` (`python3 -m unittest discover -s .claude/skills/gr0wthpilot/tests`). Its phase skills are trimmed copies of 26 marketingskills (same library and commit, MIT) in `gr0wthpilot/marketingskills/`, where Claude Code does not list them, each with a `LICENSE.md` change list; it reuses customer-research and influencer-marketing unchanged. `.agents/skills/gr0wthpilot` is a symlink to it.
- **growth-teardown:** reverse engineers how a company or app grows, at no cost, and writes a playbook for one of hcho's Products in `projects/<Product>/teardowns/NN-<target>_YYMMDD/` (`playbook.md`, a self-contained `playbook.html`, and the run's data files). It is a rebuild of [superdesigndev/treg](https://github.com/superdesigndev/treg)'s `rea-growth` skill at commit `e4f41c1a` (Apache 2.0 with Additional Terms; `growth-teardown/LICENSE.md`) whose paid catalog calls are replaced by free routes (`growth-teardown/references/free-sources.md`): Apple's lookup endpoint and live App Store pages, Wayback Machine snapshots of the listing for ratings history, REA's browser capture for the growth stack and Google's Ads Transparency Center, public job board APIs, Google autocomplete, Hacker News, Bluesky, TikTok and YouTube public pages, and a capture kit of screenshots hcho takes of the platforms whose robots.txt refuses automated readers. Every read goes through `growth-teardown/scripts/gt.py`, which checks robots.txt at every redirect hop and logs it in the run's `sources.csv`; `gt check` refuses a report that cites anything the run did not read. It never pays, signs up, posts, or contacts anyone, and never writes a Go-To-Market Package or gr0wthlab. Tests: `python3 -m unittest discover -s .claude/skills/growth-teardown/tests`. `.agents/skills/growth-teardown` is a symlink to it.
- **prd:** generates a Product Requirements Document for a new feature (clarifying questions, then a structured PRD with user stories and validation tests). Output: `.claude/agent/tasks/prd-[feature-name].md`.
- **ingest** (a global skill at `~/.claude/skills/ingest/`, available across all projects; Codex keeps an identical copy at `.agents/skills/ingest/`, so change both together): files one learning source into the right wiki, updating the source summary, affected pages, index, and log in a single pass. Run with no path, it takes the sole pending file in `inbox/`. It picks the destination from the Active wikis list in `AGENTS.md`, so it is most useful when run from within Mandu. Asset: `ingest/assets/source-summary-template.md`.
