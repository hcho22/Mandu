# Workflow with a Paycheck

The idea-selection heuristic from [[agents-are-the-new-saas]]: start from work people already pay for (an employee, agency, receptionist, coordinator, dispatcher), then deliver it cheaper with an agent.

## The 5 traits of a good agent workflow

1. **It happens all the time.** Daily is good, hourly is better.
2. **It has a clear finish line.** The job booked, the ticket categorized, the refund approved.
3. **It touches existing software.** Gmail, Slack, Shopify, HubSpot, Zendesk, Stripe - agents need tools to act and context to read.
4. **The edge cases are annoying but learnable.** Too basic gets eaten by plain automation (Zapier); pure human judgment breaks the first version. The sweet spot is repetitive work with some judgment.
5. **The buyer can feel the loss.** Missed calls, slow replies, dropped leads, empty calendar slots.

## Scoring rubric

List 20 jobs a niche complains about, then score each on: how often it happens, how expensive the pain is, how easy it is to know when done, what tools it needs, and who already owns the budget.

## Synthesis

This is a de-risking filter: it steers a builder away from both trivially-automatable and un-automatable work toward the narrow band where an agent adds real, payable value.
The "who owns the budget" question is the sharpest one - it turns a technical idea into a sale. Pairs with [[start-as-a-workflow]] (trait 4 is really "is there learnable judgment here").
