# Agentic Web

The durable hub for the shift from a human-customer internet to one where **AI agents are the customer**.
The thesis ([[startups-for-agents]]): over ~10 years, billions of agent customers with millions of wallets will transact online, and nearly every SaaS category will be rebuilt agent-native, splitting the web into a human internet and an agent internet.

## The core shift

The human customer wants persuasion; the agent customer wants structured capability, permission, and trust.
So the design target moves from a beautiful, persuasive site to a machine-usable one - and the idea generator is a single question: [[agent-native-rebuild|"what's the agent version of this?"]]

## Concepts in this area

- [[agent-native-rebuild]] - every tool category gets an agent-native version; the generator question.
- [[agent-buying-journey]] - the six-stage journey (find, evaluate, trust, transact, use, recommend) and its missing infrastructure.

- [[agent-readable-website]] - exposing docs/schemas/policies/endpoints (MCP, SDKs, OAuth, `/agents`) so agents can understand and act.

## Relationship to the rest of the wiki

- [[agent-saas]] is the mirror: it sells **agents as labor to humans**; this area builds **products for agents as the buyers**. Together they are the two sides of the agent economy.

## Synthesis

One source in, the throughline is that the interface, not just the product, is what changes: when the buyer is a program, persuasion loses to structured capability, permission, and trust.
That reframes a lot of "marketing/growth" work as engineering (capability manifests, MCP tools, agent analytics), which is a builder-favorable shift.
For hcho the reusable angle is that agent identity, permissions, wallets, and receipts are a threat-model/validation surface - the same edge that recurs everywhere in this wiki, now pointed at the machine-to-machine economy. The open question worth watching is "agent analytics / agent conversion," which nobody has defined yet.
