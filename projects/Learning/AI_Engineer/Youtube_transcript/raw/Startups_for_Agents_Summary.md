# Startups for Agents: Building for the Agentic Web

> **Video Tutorial Summary — Startup Ideas Podcast**
> A primer on how the internet is shifting from human users to AI agents as customers — and the products, infrastructure, and startup opportunities that shift creates.
>

## Overview

The speaker argues that a large, under-discussed shift is happening online: for decades the end users of the internet were humans, but increasingly **AI agents are becoming the customer**. Over the next 10 years he predicts a market of **billions of agent "customers" with millions of wallets**, and that almost every existing SaaS category will be rebuilt in an "agent-native" form.

The episode walks through how the agent buying journey differs from the human one, what agents uniquely need (identity, tools, inbox, memory, wallet, receipts), concrete real-world examples, how to make a website "agent-readable," what all of this changes for startups (notably the move from **SEO to AEO**), and a rapid-fire list of startup ideas. The core method offered: take any popular tool and ask *"what is the agent version of this?"*

## 3. Old web vs. agent web
*1:55*

- **Old web:** humans searching, reading, comparing, clicking, and buying. Your beautiful website was built to win human attention.
- **Agent web:** agents discovering, evaluating, invoking tools, paying, and renewing. Your company therefore has to be **machine-usable**.

`[RULE]` **The human customer wants persuasion; the agent customer wants structured capability, permission, and trust.** (The speaker presents this as his framing of how the two web models differ.)

## 4. The agent buying journey
*2:26*

- Worth mapping out because understanding the agent's identity, desires, and incentives is what lets builders create high-revenue, high-value companies.
- **Who are "the agents"?** Everyone will have **personal agents** (in their pocket / on the web) and **business agents**.
- **The journey has six stages:** Finding (e.g., "find a payroll tool for 40 contractors") → Evaluating (docs, pricing, APIs, reviews) → Trust (checking policy, limits, identity) → Transacting (paying, booking, signing, subscribing) → Using tools (filing tickets, changing settings) → Recommending (telling other agents what worked).
- The "weirdest part": agents **recommending tools to other agents**. An early glimpse was **Moltbook**, a social network for agents that was acquired by Facebook (Meta).
- **The opportunity:** every step has missing infrastructure, because the old internet assumed a *person* was doing the work.

`[OPINION]` "It's pretty inevitable that agents are going to be everywhere and will outnumber humans." Also predicts that Moltbook was "just the tip of the iceberg" and that more agent-only social products are coming.

> 🧰 **Tools / proper nouns mentioned**
> `Codex` · `Claude Code` · `OpenClaw` · `Hermes` · `Moltbook` (→ acquired by Facebook/Meta)
> *Caption-derived names; "OpenClaw" and "Hermes" are cited as example agent/coding tools.*

## 5. What agents need — 6 building blocks
*4:43*

- **Identity** — Who is this agent acting for?
- **Tools** — What actions can it safely invoke?
- **Inbox** — Where do OTPs, docs, and threads land, and where can it reply?
- **Memory** — What does it know about my preferences and rules?
- **Wallet** — What can it spend, and who approves it?
- **Receipts** — What did it see, decide, change, and buy?

> 💡 **Mental model**
> Think of an agent like an **employee**: as it gains trust, you give it more — e.g., hand it a credit card, then raise the spending limit over time. Identity → tools → wallet maps onto how trust is granted to a new hire.

## 6. Concrete examples
*5:33*

- **AgentMail** — described on its site as "the email inbox API for AI agents." It gives agents their own email inbox, the way Gmail does for humans — i.e., the agent infrastructure layer for email. Backed by Y Combinator (YC).
- **Stripe agent wallet** — Stripe recently launched a way to give your agent a wallet. Example use: a purchasing agent that buys software with **spend caps, approval rules, shared payment tokens, and an audit trail**.
- **Support** — a user's agent files a ticket, attaches logs, asks for the refund, follows up, and escalates when ignored.
- **Procurement** — a CFO agent compares 12 vendors, reads SOC 2 docs, negotiates terms, and recommends the one that fits policy.
- **MCP server** — a SaaS app exposes tools to agents (search customers, create invoices, refund orders, update tickets, pull reports) so the agent **doesn't scrape the UI**.
- **Travel agent (local-business example)** — books dinner, changes the reservation, calls the hotel, pays the deposit, and updates the calendar.

`[OPINION]` On AgentMail: "Huge opportunity... I heard they're doing really well — not surprised." He also expects "a lot more support agents" and more fintech examples like agent wallets.

`[RULE]` If agent traffic on the internet exceeds human traffic, then software and technology must be built to service agents — which is where the opportunity lies.

> 🧰 **Tools / proper nouns mentioned**
> `AgentMail` (email inbox API for agents) · `Stripe` agent wallet · `MCP` server · `YC` (Y Combinator) · `SOC 2` · `Gmail`

> 💡 **Tip**
> The speaker says he personally needs to **see concrete examples** (an inbox for an agent, a wallet for an agent) before the abstract idea "clicks." Use specific scenarios to pressure-test whether an agent product makes sense.

## 7. Building an agent-readable website
*8:25*

- **A human-readable homepage** typically has: brand, video, copy, social proof, a demo, and pricing.
- **An agent-readable homepage** instead exposes: structured docs, schemas, policies, examples, and endpoints.
- In practice, "agent-readable" means: **MCP tools, SDKs, OAuth, checkout, a sandbox, and receipts**.

`[RULE]` If an agent can't understand what you do and can't safely take an action with you, you are effectively **invisible to that agent**.

> 💡 **Actionable advice**
> Structure your site around agents and create dedicated agent entry points — e.g., a `/agents` path (`yourwebsite.com/agents`) and other agent-specific endpoints. The speaker calls this a "huge opportunity."

> 🧰 **Building blocks named**
> `MCP tools` · `SDKs` · `OAuth` · `checkout` · `sandbox` · `receipts` · `schemas` · `/agents`

## 8. What this changes for startups
*9:31*

- **SEO → AEO.** Optimize for agents deciding who to cite, trust, and recommend. Agents will both ask other agents for recommendations and use computer-use tools like **ChatGPT** and **Perplexity** — so you want to rank well there.
- **Forms → tool calls.** The call-to-action becomes an action endpoint.
- **Support docs → executable support.** Agents perform the refund, return, reschedule, troubleshooting, and escalation.
- **Landing pages → capability manifests.** Agents care less about slogans and more about what they can actually *do* with your product.
- **Sales calls → agent procurement.** Buyers send agents to a short list before a human ever appears.
- **Analytics → agent analytics.** Which agents visited? What did they ask? Where did they fail or bounce?

`[OPINION]` The speaker is preoccupied with one open question he "can't stop thinking about": what does agent analytics look like, and how do you optimize the *conversion rate for agents?*

> 💡 **Context / why it matters**
> Earlier in his career he paired "voice of customer" survey data with Google Analytics to lift conversion rates from **1% to 4%** — which he frames as the difference between millions of dollars. The implication: the same conversion-optimization discipline now needs an agent-native equivalent.

> 🧰 **Tools / proper nouns mentioned**
> `AEO` (Answer/Agent Engine Optimization) · `ChatGPT` · `Perplexity` · `Google Analytics`
