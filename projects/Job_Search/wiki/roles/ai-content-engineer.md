# AI Content Engineer

## What it is
A hybrid of ML engineer, benchmark builder, and technical writer.
Builds real benchmarks and runs real experiments, then publishes the findings as technical content at high velocity (blog pace, not paper pace).
Explicitly not DevRel or marketing - it is engineering work whose output happens to be published.
Straddles both buckets: it is builder work grounded in an evals/benchmarking core, plus a public-writing surface.

## Day-to-day
- Design, build, and maintain benchmarks (LlamaIndex: document parsing/understanding).
- Run experiments; translate findings into publishable artifacts quickly.
- Publish weekly: benchmark reports, technical comparisons, tutorials, open-source examples.
- Stay current with the landscape (models, papers, competitors); read and synthesize papers rapidly.

## Required qualifications and skills

Must-have:
- [[python]] - production Python; strong SW fundamentals; ML engineering a plus.
- [[technical-writing-benchmarking]] - the defining skill: write clearly, quickly, authentically about technical topics; build evaluation frameworks/benchmarks; bias toward shipping.
- [[eval-pipeline-design]] - benchmarks and evaluation frameworks are the core deliverable.
- Modern ML (CV, NLP, or multimodal); read/synthesize research fast.

Preferred:
- VLMs / transformers / document AI (OCR, layout, table extraction).
- Existing technical-writing portfolio; active in ML/AI communities.
- [[rag-systems]] - LLM applications and RAG.
